# libwally-core Project Structure

## Directory Layout

```
libwally-core/
├── src/                    - C source (parser, satisfier, PSBT, etc.)
│   ├── ctest/              - C unit tests
│   ├── test/               - Python tests (via ctypes binding)
│   ├── secp256k1/          - vendored secp256k1 (don't modify)
│   ├── descriptor.c        - descriptor parser, ms_node AST, miniscript types
│   ├── psbt.c              - PSBT serialization, signing, finalization
│   ├── script.c            - Bitcoin Script helpers (varint, tapleaf_hash, etc.)
│   └── miniscript_decode.c - (NEW) tokenizer + AST decoder (port of rust-miniscript)
│   └── miniscript_satisfy.c- (NEW) AST satisfier (port of rust-miniscript)
├── include/                - public headers
│   ├── wally_descriptor.h  - descriptor public API
│   ├── wally_psbt.h        - PSBT public API
│   └── wally_script.h      - Script public API
├── docs/source/            - Sphinx docs
├── tools/                  - utility scripts (uncrustify wrapper, etc.)
└── .cm/                    - cm orchestrator state (this directory)
```

## Module Organization

- **descriptor**: parser, AST types (`ms_node`), `g_builtins[]` table mapping miniscript fragment names to type properties + verify/generate functions
- **psbt**: PSBT v0/v2 serialization, signing path, finalizers (`finalize_p2pkh`, `finalize_p2wpkh`, `finalize_p2wsh`, `finalize_p2tr_script_path`, etc.)
- **script**: low-level Bitcoin Script helpers (`varint_to_bytes`, `varint_get_length`, `tapleaf_hash`, opcodes)
- **musig**: BIP-327 MuSig2 wrappers around libsecp256k1-zkp
- **miniscript_decode** (new): tokenizer + recursive descent decoder ports (rust-miniscript-derived)
- **miniscript_satisfy** (new): AST-based satisfier with `ms_satisfaction { has_sig, weight, witness, missing_*[] }`

## Key Components

### `ms_node` AST
- **Purpose:** typed AST for parsed miniscript expressions
- **Location:** `src/descriptor.c:213` (will move to `src/descriptor_int.h` in Phase 1)
- **Dependencies:** none — plain C struct with `kind`, `builtin`, `child`, `next`, `parent`, `type_properties`, `flags`, `data`
- **Key fields:** `kind` (one of `KIND_*`), `builtin` (1-based index into `g_builtins[]`)

### `g_builtins[]`
- **Purpose:** central table of every miniscript/descriptor fragment with name, kind, type properties, child count, verify/generate function pointers
- **Location:** `src/descriptor.c` (will move to `src/descriptor_int.h` in Phase 1)
- **How to extend:** add a row in this table; the parser/generator/verifier dispatch automatically

### Finalizers
- **Purpose:** assemble the final witness/scriptSig from a fully-signed PSBT
- **Location:** `src/psbt.c:5664+` (`finalize_p2pkh`, `finalize_p2wpkh`, `finalize_p2sh_wrapped`, `finalize_p2wsh`, `finalize_p2tr_script_path`, etc.)
- **Status:** `finalize_p2wsh` is a stub (`return false; /* TODO */`); will be implemented in Phase 7

## Data Flow (this project)

```
PSBT input
  → leaf script bytes (PSBT_IN_TAP_LEAF_SCRIPT or PSBT_IN_WITNESS_SCRIPT)
  → tokenize_script(bytes) → token stream
  → decode_script_to_node(tokens) → ms_node AST
  → satisfy_node(input, ast, ctx_flags) → ms_satisfaction
  → wally_psbt_input.final_witness
```

## Important Patterns

### Pointer-and-length convention

libwally APIs take `(unsigned char *bytes, size_t len)` pairs rather than relying on null-terminated strings. Tokenizer/decoder follow the same convention.

### Output via pointer parameter

Functions return `int` status (`WALLY_OK`/`WALLY_EINVAL`/...) and produce results via output pointers. The struct `wally_descriptor` (typedef'd to `ms_ctx`) is opaque to callers.

### Composite-key map lookups

Maps in `wally_psbt_input` (preimages, taproot_leaf_signatures) use composite keys `[type_byte || hash]` or `[xonly_pubkey || leaf_hash]`. Lookups via `wally_map_find` return `*written = 0` on not-found, else `index + 1`.

### Stack copy + override pattern

Public APIs that take `const struct wally_descriptor *` make a stack copy (`memcpy(&ctx, descriptor, sizeof(ctx))`), override per-call fields (`variant`, `child_num`, `multi_index`, `path_buff`), use, and discard. Avoids mutating the caller's input.
